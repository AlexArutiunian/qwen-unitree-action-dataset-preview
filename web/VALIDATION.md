# Sample 91 validation (2026-09-07)

## Passed

- `npm test`: 6 tests, including actual @mujoco/mujoco 3.12.0 WASM loading the official G1 MJCF and MJB.
- Exact endpoint angles for all eight sample-91 joints, all remaining qpos unchanged from qpos0, finite geometry transforms, positive anatomical left wrist height and negative-Y right extension.
- MJCF/MJB endpoint geometry parity within 1e-10 in the real WASM runtime.
- `npm run release`: production Vite build with relative URLs, packaged into demo/.
- Chrome: the sample loads from MJCF; final UI telemetry reports 0.000000 degrees maximum target error and unchanged remaining joints.
- Chrome: play, reset, slider seeking, speed 0.25x, orbit drag while motion time advanced, front view.
- Chrome: a 390x844 iframe (real nested viewport, not physical phone emulation) loads and plays the sample. Extended left arm and feet remain visible together.
- Chrome: the production build loads from a subpath and accepts `?format=mjb` using the generated binary, without stalling.
- WebGL-unavailable behavior was exercised in the real browser: interactive SVG fallback renders the same MuJoCo-computed geometry transforms rather than a video.

## Limits

The available cloud Chrome reports GL_VENDOR=Disabled and GL_RENDERER=Disabled. WebGL rendering could not be visually verified here. Browser interaction checks therefore exercise the lower-detail SVG fallback. Primary CAD-mesh forward kinematics and binary loading are verified in WASM tests, but those are not a visual GPU test.

The private g1_inspire_clean.xml and previous large MJB were inaccessible. This release uses the official 29-DoF G1 and executes sample 91 only. It does not claim finger parity, verification of all dataset actions, or a reproduced root cause for the old private MJB stall.

## Payload (uncompressed)

- Primary MJCF + visual meshes: 3,630,837 bytes, 71,878 triangles.
- Software fallback MJCF + visual shells: 975,237 bytes, 18,766 triangles.
- MuJoCo WASM: 10,125,418 bytes (Vite gzip estimate about 2.51 MB).
- Losslessly gzipped MJB files are optional diagnostics and are not fetched on the default loading path.
- No dataset payload is loaded or generated by the demo.
